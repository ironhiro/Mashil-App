### 9.3 상세 주소 제거 규칙과 재검증 (2026-11-14)

**원칙 (Kakao 권장 사항):** 조회 질의에서 **상세 주소를 뺀다.** 도로명은 건물번호까지, 지번은 본번-부번까지만 남기고 그 뒤의 건물명, 층, 호, 출입구, 쉼표 뒤 부가 정보를 지운다. 상세 주소는 입력 형태가 제각각이라 정확한 검색 결과를 보장하기 어렵다. 원문은 raw와 `toilets.road_address`에 그대로 두고, 질의용 문자열만 따로 만든다.

**질의 생성 규칙 (순서대로 적용):**
1. 괄호 안 내용 제거, 시도 오타 사전 (`서을` → `서울`)
2. `N번지 M호` → `N-M`, `번지` 제거, `-0` 제거
3. **첫 쉼표 앞까지만** 사용
4. 띄어쓰기 없는 주소는 행정구역 접미사(시·군·구·읍·면) 뒤에 공백 삽입
5. **`○○로 N번길`은 `○○로N번길` 한 토큰으로 붙인다** (도로명의 일부라서)
6. 도로명과 건물번호 사이, 리·동·가와 번지 사이에 공백 (`길주로623` → `길주로 623`, `관천리75` → `관천리 75`)
7. 도로명이면 **마지막 `…로/길` 토큰 + [지하] 건물번호**까지, 지번이면 **`…동/리/가` + [산] 본번-부번**까지 자른다

**결과 검증 (필수):** 자른 질의로 찾은 결과는 **도로명(또는 법정동)과 건물 본번(또는 지번 본번)이 원문과 같을 때만** 채택한다. 첫 시도에서 규칙 5가 없을 때 `장안로 65번길268`이 `장안로 65`로 잘려 **다른 실제 주소에 조용히 매칭**됐다. 실패보다 위험한 오류라서 검증으로 막는다. 검증에 실패하면 NoMatch로 처리하고 이슈를 남긴다.

**재검증 결과 (실패 14건 + 결과 여러 건 7건 = 21건 재조회):**

| 구분 | 전 | 후 |
|---|---|---|
| 실패 14건 | 0건 매칭 | **3건 매칭** (`문암리 71번지 3호`, `중앙로 지하 60, 출입구`, `서귀동 305-1, 300-19`). 오매칭 0건 |
| 결과 여러 건 7건 | 7건 모호 | **3건이 1건으로 확정** (쉼표 뒤 건물명 제거 효과) |
| 남은 모호 4건 | | 리 단위만 있거나(`용월리 239-3`, `양촌면 419-1`) 같은 주소가 도로명·지번 두 문서로 나온 경우 → `개방자치단체코드`로 시도·시군구를 걸러 선택 |
| 남은 실패 11건 | | 존재하지 않거나 바뀐 주소(`춘천로 22`, `홍원길 127`), 행정동 표기(`대연5동`: 지번 검색에는 법정동이 필요), 번호 오류(`3길21824`) → 관리자 수동 좌표 |

**전체 추정 수정 (샘플 기준, ±2%p 오차 가능):**
- 보정 규칙 없이: 약 4.1% → 약 2,200건 실패
- 보정 규칙 적용 후: 실패 14건 중 3건만 회복되어 **약 3.2% → 약 1,700건이 관리자 검수 대상** (앞서 추정한 1,000건보다 많음)
- 행정동을 법정동으로 바꾸는 규칙(`대연5동` → `대연동`)을 추가하면 일부가 더 회복될 수 있다. 행정동 명칭 사전이 필요하다 (P2에서 검토)
- 검수는 시군구별로 묶어 일괄 처리할 수 있게 한다 (ADM-03)
